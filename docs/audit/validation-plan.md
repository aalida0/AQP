# Required validation tests

This is an implementation handoff, **not a record of passed tests**. Fixtures and mocked commands can be added without running production. Any integration, rebuilding, event generation or submission below requires a separately authorized task.

| Priority / test | Minimum acceptance criteria | Findings covered |
|---|---|---|
| High — source/card inventory | Read originals without imports or writes; normalize card names; report duplicate/conflicting keys. Capture model/restriction, process ladder, beam energies, PDF metadata, cuts, scale/weight switches, Delta/folding and source hashes. Reject incompatible card/source/grid identities before reuse. | P02–P05; recovery |
| High — complete LHE parser fixtures | Validate root/init blocks, all event-header fields, declared particle counts, particle records, finite four-momenta/weights, event ordering/closure and declared alternative-weight coverage. Reject header-only events, truncation, malformed particles, duplicate event delimiters, missing init and trailing events after root closure. | Existing [E21](evidence.md#e21):26–68 mainly checks tags and nominal XWGTUP; it does not parse particle records. |
| High — weight diagnostics | Independently verify N, Σw, Σ|w|, Σw², sign fractions and N_eff on constant, variable, signed, zero and cancellation fixtures. Preserve weight names/IDs and detect nonfinite aggregate results. Do not equate sign dilution with total effective statistics. | P01; physics-generator report |
| High — publication/failure injection | Stub generator/setup/copy commands. Cover setup failure, successful body plus failed copy, missing required artifact, disk failure, TERM, pre-existing partial output and repeated attempts. Success requires verified durable artifacts and an atomic completion manifest; failure must block downstream execution. | C01, C04–C05 |
| High — input/staging identity | Mutated archive with a present checksum sidecar must fail. Mixed revisions and interrupted downloads must fail atomically. Verify selected archive member identity and reject ambiguous event-member selection. | C02–C03; [E15](evidence.md#e15):263–268 selects the first matching member. |
| High — checkpoint parity fixtures | Compare native and reconstructed per-channel schemas, seven-field result mapping, exact channel set/order, folding, cards and grid/source fingerprints. Reject missing/mixed channels, nonfinite fields, incompatible folding, changed PDF/cuts and changed executable provenance. Do not load untrusted pickles. | Recovery gap; [E11](evidence.md#e11), [E12](evidence.md#e12), [E13](evidence.md#e13) |
| High — isolated Fortran tests | Bias kinematic cases and soft/collinear/zero limits; Sudakov lower/upper boundaries including the exact tolerance. Record compiler/flags and source/object/executable identities. | Fortran report |
| High — effective shower settings | Verify resolved includes and final FxFx controls/hook list, input LHE identity, multiplicity/flavor and thresholds. Distinguish TXT dummy mode from the external-LHE shower. Inspect output records independently of log markers. | FxFx report |
| High — physics normalization closure | Trace bias compensation and normalization into final selected weights. Compare signed yields/spectra to a justified reference with calculated uncertainties; report achieved integration precision. | P01, P05 |
| High — merging/variant comparisons | Define jets/bins/statistical criteria first; examine weighted jet-resolution distributions, exclusive/inclusive multiplicities and hard tails. Separate folding comparisons from standard/Delta and merging-scale comparisons. Document uncertainty treatment and NNLO-PDF/NLO-ME prescription. | P03; FxFx report |
| Medium — reliability/performance benchmark | Measure generation, shower and integration costs separately across independent seeds; verify reserved/used resources and durable outputs. Compare precision and useful event throughput, not negative-count fraction alone. | C05; weight diagnostics |

Current audit verification: source inspection, consultant source walks, file hashing, and byte comparisons only. Future test reports should list input identity, implementation revision, observed/expected outcome and retained evidence; a single aggregate PASS must not imply all rows passed.
