# AQP V+jets: ATLAS styling of unmodified Rivet plots

## Strict rule: visual changes ONLY

Use the original YODA-generated plot scripts (`<observable>.py`) and
the exact associated numerical exports (`<observable>__data.py`) generated
by the existing `rivet-mkhtml` plotting campaign. **Do not reconstruct
histograms from the exports. Do not renormalize them.**

`aqp_vjets_mplhep_plot.py` executes the original generated plot script
with a narrowly limited stylesheet/figure edit:

- `plt.style.use(hep.style.ATLAS)` and plot font/figure sizes.
- `ATLAS Simulation Internal` label **inside** the upper panel; the
  Rivet-generated legend is unchanged and remains inside the axes.
- Align the rightmost x-axis caption within the figure to prevent clipping.

**Every other Rivet-generated instruction stays identical**, notably:

- each configuration's original bin edges and bin centers;
- original y-values and **normalization** (not unit area);
- original line colors (`#EE3311`, `#3366FF`, `#109618`,
  `#FF9900` in the common four-way plots);
- original legend texts (`S111`, `D111`, `D221`, `D441`) and placement;
- original x/y titles, scientific units, limits, log/linear scales;
- exact **main-panel** `dataf['yerrs']` and `dataf['xerrs']`;
- exact **ratio-panel** `dataf['ratio0_yvals']`,
  `dataf['ratio0_yerrs']`, and `dataf['ref_xerrs']`;
- the source's step-histogram drawing, variation curves, and
  generated errorbar semantics.

**Requested styling refinement:** the two stepped histogram outlines
(upper panel and ratio panel) are drawn at **1.8× the original line
width**, by changing only their `ax.plot`/`ratio0_ax.plot` linewidth
arguments in an in-memory copy of the autogenerated plotting script.
Rivet's actual error-bar calls and error-bar line widths are **not**
changed, nor are the original bin uncertainties, markers, or colors.
This is the sole intentional exception to identical line widths.

The wrapper **does not call** `normalize()`, `hep.histplot()`,
or compute any new ratios/error bands. No textual footnote/footer
is added to any image. The former diagnostic implementation was replaced
because it changed physics-facing plot properties.

## Distinguish rendering fidelity from physics validation

The original YODA samples have known inconsistent cross-section metadata
and a high-pT bias. This styling-only pass deliberately **does not** correct
the numerical output or certify absolute normalization. A re-normalization,
if physics requires it later, must be done as a separate documented
validation procedure with verified event weights and cross sections,
**not** inside a presentation styling script.

Remaining ATLAS/CMS routines and W kT-splitting full production are out
of scope for this pass. `main` is not changed.
